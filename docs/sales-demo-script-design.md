**当前交付状态：内部脚本模板，尚未完成真实数据绑定，不可对外逐字照读。** 已确认的目标是：店员向顾客讲产品、验证相关产品信息，并解释在满足销售规则后顾客实付最低的可行报价。用户已确认四级名称为“基准价 / 平台优惠 / 身份权益 / 换新国补”，名称来源标记为 `user_confirmed`；此处列示不是计算顺序。已读P4三份仍为空模板，实际优惠规则、执行顺序、资格和数字尚待ima来源核验。下面的引用槽是开发绑定位置，不是顾客文案。

## 交付形态与责任

最终候选稿必须同时包含：逐字台词、店员操作动作、六段时段预算、资格核对条件、产品验证动作、顾客最终报价、报价有效期及到店行动引导。只交大纲、讲解要点、产品卖点列表或“约三分钟”文本都不满足该产物要求。

应用编排器负责解析只读引用、验证身份/报价状态、绑定版本、计算哈希、计时记录及可展示门禁。写作模型只组织顾客可见的措辞与操作说明，不计算报价、不确定顾客资格、不读取价格底层规则，也不授予最终展示权限。

三分钟是标准店员演练总时长目标，六段预算合计 180 秒，包含计划内的店员讲话、指示、操作和必要观察。模型生成、资料加载、报价计算、网络等待不得算作产品展示。顾客较长回答、额外问题、额外资格核验、现场故障排查另计；遇到这些情况，记录为中断/扩展分支，不把等待塞进三分钟成绩。

## 场景适配、多个候选与选定SKU

先以顾客场景、必要软件/设备及其他硬约束筛选适配产品，可保留一个或多个有证据的候选，不为凑数推荐。只有适配候选进入逐SKU报价；每个SKU分别在有效规则/资格下求顾客最低实付，再在可比条件下有据比较。不能把不适配但便宜的型号排成首选，也不能混用候选A的卖点与候选B的价格。

本节点消费已冻结的适配/比较依据及顾客最终选定SKU，不重新排序或心算跨SKU价格。店员须讲清推荐理由、取舍和已选版本；未选定SKU时先返回澄清/选择分支，不把多个候选报价拼成一份三分钟成品。其他候选与比较可作扩展问答，三分钟主体只绑定最终选定SKU及其 `customer_quote_ref`。推荐、选定SKU或关联证据变化也使旧脚本失效。

## 输入与只读报价边界

| 绑定项 | 最低内容与校验 | 绑定来源 |
| --- | --- | --- |
| `customer_need_ref` | 顾客实际确认的主要任务、必要软件/设备条件；推断不得写成顾客陈述 | 当前任务的已确认需求 |
| 适配/比较结果引用 | 一个或多个适配候选、各自事实/报价引用、可比条件、推荐理由/取舍与最终选定SKU；字段映射主合同 | 已核验场景适配结果及获准客户比较摘要 |
| `product_identity_ref` | 完整型号/年款/系统、主张相关配置与款式；演示机身份与拟售 SKU 的关系 | 当前 ima 取证结果及授权门店演示机记录 |
| `product_fact_refs[]` | 拟讲事实、单位、适用条件、限制和来源定位；未解决冲突为阻断 | 指定 ima 知识库的当前最小证据 |
| `demo_action_plan_ref` | 操作步骤、授权样例/测试条件、预期可观察项、失败话术；每一步能在现场完成 | 经门店确认可行的演示计划及相关产品证据 |
| `customer_quote_ref` | 服务端解析出的当前顾客报价只读摘要，已核验当前授权与规则适用性 | 确定性报价服务 |
| `cta_ref` | 允许展示的门店信息、办理/预约动作；远程或已到店情境 | 当前门店公开业务资料 |

`customer_quote_ref` 是引用，不是提示词中的内部定价表。应用只向本节点提供 `CustomerQuoteSummary`，至少包含：

- 对应的产品/SKU 展示信息、数量、币种与顾客可见最终应付文本；金额以报价服务格式化结果为准。
- 允许向顾客说明的价格构成、适用资格与必要核对条件、支付/交付条件；不需要的条件不扩写。
- 顾客资格的已核验/待核验结论及必要后续动作；待核验时不能宣称已获得优惠。
- 明确有效期（含时区）、当前是否仍可引用，以及允许的最低实付比较范围说明。
- 当前任务绑定的 quote 引用/版本指纹；该指纹由服务端提供，不由模型创建。

本节点不得接收或索取内部底价、进货成本、返利、利润、审批阈值、内部四级全量候选表或审批记录。若上游误传，停止生成并报告输入越界，不将其复述到台词、引用清单或模型自检。顾客可见摘要是否允许披露由服务端决定，不能由模型从机密信息中自行挑选。

“最低”只限本次已核验、当前顾客有资格且满足销售约束的候选集合，并按顾客最终实付比较；不扩展成全网、全店历史或所有未来活动最低。只有服务端确实返回这一结论时才能使用该表述。没有可执行规则时返回不能报价，不以四级标签、旧价或“以实际为准”补造数字。

## 生成与使用门禁

1. 需求、适配/比较理由、最终选定SKU、产品身份、拟用事实、演示动作和顾客报价逐项绑定；不存在的引用、未读原文、空模板、过期规则、未知资格不得当作已支持。
2. 生成逐字台词与动作分镜；对所有可验证原句建立事实引用，报价原句仅绑定 `customer_quote_ref` 对应摘要。
3. 应用核对引用、型号、金额原样一致、有效期、动作可行性、敏感信息和文本完整性；独立模型的审查仅作为输入之一。
4. 店员真实按稿试讲并计时。**170—190 秒可作为暂定项目验收窗，是本方案提出的容差建议，并非用户原话或行业统一标准。** 超出时先调整有据表达和动作安排，不能跳过必要核验动作或删掉价格限制来凑时长。正式容差可由用户修订。
5. 对外使用前由应用重新验证引用仍有效，尤其在报出价格前检查报价未失效；需要重新计算或等待时中断标准演练，不提前报旧价。

报价引用、金额、资格、适用条件、有效期或底层价格政策变化，使已绑定脚本失效；产品/SKU、事实、顾客需求、演示动作及门店 CTA 的相关变更同样触发受影响版本重建。**报价改变后 `script_invalid=true` 由应用设置**，不能只替换台词中的一个数字后沿用旧核验/计时记录。

编排器保存脚本与所有依赖版本/哈希。模型不填写可信租户身份、报价有效状态、核验通过或导出许可。读过脚本不等于看过原图、跑过现场演示或已向顾客确认资格。

## 六段内部绑定模板

以下 `{{binding:…}}` 只供开发识别绑定点；实际运行时先解析、核验，再生成自然逐字台词。模板不是已绑定成品，不得直接粘贴给顾客。涉及实际演示结果的成功/未成功分支在现场观察后选用，不能预先承诺成功。

| 时段 / 预算 | 逐字台词模板（内部） | 店员动作与必须保留的判断 |
| --- | --- | --- |
| 0—20 秒 / 20 秒：确认任务与讲解范围 | “您好，针对您确认的‘{{binding:customer_need_ref.confirmed_task}}’，推荐理由是{{binding:recommendation.verified_reason}}。我们先核对您已选版本，再现场看一个和您任务相关的动作，最后把您适用的报价、条件和有效期讲清楚。有还没确认的地方，我会直接说明。” | 出示已确认任务和有据推荐理由；候选可多个，本次选定SKU必须明确。若顾客纠正任务或未确认需求，停止标准讲解并补充需求；不假装已确认。 |
| 20—45 秒 / 25 秒：核对型号与配置 | “本次介绍的是{{binding:product_identity_ref.customer_display_name}}，对应{{binding:product_identity_ref.relevant_configuration}}。请和我一起核对这里的型号与配置。{{binding:product_identity_ref.demo_to_sale_relation_sentence}}。后面的产品说明和报价都只对应这个已确认版本。” | 指向实际机身/系统/授权标签，按动作计划核对型号、系统及涉及的配置。演示机与拟售 SKU 不同必须按已核验关系明说；不相符且关系不清时停止，不借相近型号继续。 |
| 45—85 秒 / 40 秒：讲一个相关卖点并验证 | “针对您要做的{{binding:customer_need_ref.confirmed_task}}，先看{{binding:product_fact_refs.primary_fact.customer_sentence}}。它成立的条件是{{binding:product_fact_refs.primary_fact.required_conditions}}。接下来我按{{binding:demo_action_plan_ref.customer_steps}}操作，您可以重点看{{binding:demo_action_plan_ref.observable_items}}。” | 实际执行已准备的动作，不用后台加载动画或沉默等待替代验证。只用获准的演示账号/样例；开始前条件不满足则走待验证分支。按实际观察选用计划中的结果台词，不预写“已成功/提速多少”。 |
| 85—120 秒 / 35 秒：说明结果与使用边界 | 成功观察分支：“刚才我们实际看到的是{{binding:demo_action_plan_ref.observed_result_sentence}}。这一步只说明{{binding:demo_action_plan_ref.supported_scope}}。对您的{{binding:customer_need_ref.remaining_dependency}}，还需要{{binding:demo_action_plan_ref.remaining_verification}}，我不会把这次演示当作所有环境都适用的保证。” 未完成分支：“这一步还没有完成验证，我现在不能把它说成已经支持。我们先记下要核对的条件，确认后再向您说明结果。” | 展示实际结果并记录观察，不把一次打开样例升级成全部软件/工程兼容。若关键购买门槛验证失败，明确暂停推荐；不能靠另一个便利卖点覆盖门槛失败。无剩余待核项时由绑定数据生成相应有据边界句，不强塞占位问题。 |
| 120—155 秒 / 35 秒：核对资格并解释实付 | “按这次已经核验适用的销售规则，{{binding:customer_quote_ref.minimum_payable_scope_sentence}}。您这次购买{{binding:customer_quote_ref.product_and_quantity_sentence}}，最终应付是{{binding:customer_quote_ref.formatted_customer_payable}}。这个结果适用的条件是{{binding:customer_quote_ref.customer_visible_conditions_sentence}}；{{binding:customer_quote_ref.eligibility_confirmation_sentence}}。{{binding:customer_quote_ref.customer_visible_breakdown_sentence}}。” | 报价前确认 quote 引用仍有效，展示顾客可见摘要而非内部价格表。逐项核必要资格，不能直接勾选通过；待核验资格、配置/数量变化或报价刷新失败时不读金额段，使用安全待核验话术并中断正式报价。无获准构成明细时省略该句，不反推计算。 |
| 155—180 秒 / 25 秒：有效期、复述与行动 | “这份报价有效至{{binding:customer_quote_ref.valid_until_display}}，并以刚才核对的产品、数量和适用条件为前提。您可以再确认一次型号、最终应付和这些条件。{{binding:cta_ref.customer_sentence}}。如果条件变化，我们会重新核价，再向您说明。” | 指向报价摘要中的有效期和适用范围。远程顾客用已获准的到店/预约引导；已在店顾客引导继续现场核对或办理。没有已核验地址、时间、库存或服务时不承诺。 |

模板句子的扩缩仅用已绑定、与本次决策相关的信息；不能为凑时长添加性能、服务或优惠承诺。最终稿不得出现原始 binding 标记、内部 ID、空白金额或“待填”字段。

## 现场分支与可直接使用的安全话术

当前缺少真实价格政策与四级规则，允许输出的是短待核验话术，而不是满篇占位的对客三分钟报价稿：

> “目前这份报价还没有完成核验，我先不向您报最终金额。我可以先帮您核对具体型号、配置和适用资格；确认可用规则后，再把最终应付、适用条件和有效期一起说明。”

产品证据也不足时：

> “这项产品信息我还没有核实，暂时不向您作承诺。我先记下您要完成的任务，核对准确版本和适用条件后，再给您说明。”

顾客长答/追问时：

> “这个问题会影响选择，我们先把它确认清楚，再继续介绍和核价。”

这些话术没有虚构数字、型号、库存或承诺，可以在相应真实缺口下使用；它们不表示已完成三分钟演练，也不替代正式报价。

## 产物结构与验收

应用严格 Schema 优先；下列为节点须承载的信息，不授权模型新增可信元数据：

- `script_type` 固定表达“店员向顾客讲产品并解释报价”；`segments[]` 六段，包含时段、预算秒数、逐字台词、店员动作、适用/失败分支、事实与报价引用。
- `qualification_checks[]` 记录须核什么、摘要给出的状态、未核时该停止哪句；不包含顾客不必要的敏感证明原文。
- `product_checks[]` 记录演示身份、必要条件、动作、可观察项与未通过分支；实际结果/时间由应用或人员记录，模型不补填。
- `claims[]` 将原句定位到段落，引用已存在事实或 `customer_quote_ref`；`open_items` 和 `blockers` 说明缺口，不能夹入内部机密。
- 缺绑定时 `script` 不返回可误用成品，只交内部模板状态与必要缺口；`safe_customer_message` 可给上文短话术。候选绑定完成也不等于已通过应用核验和演练。

验收至少覆盖：

| 场景 | 必须结果 |
| --- | --- |
| 名称已由用户确认，但已读P4仍空、规则/顺序/数字未核实 | 保留四级名及user_confirmed来源，不猜叠加或全部享有；无最终金额/可照读成品，提供短待核验话术 |
| 场景得到多个候选 | 先适配筛选、每SKU独立最低实付、有据比较；脚本讲清推荐理由，只绑定最终选定SKU |
| 报价摘要有效且全部绑定 | 逐字台词、动作、六段预算、必要资格、产品验证、实付/条件/有效期及 CTA 均齐全；金额与摘要原样一致 |
| 资格待核验、规则冲突/过期或无可行方案 | 不宣称有优惠/最优价，不把“以实际为准”作为无据数字的保护语 |
| 报价或产品依赖在生成后变化 | 旧脚本失效、停止展示金额段；重新生成/核验受影响内容，旧计时不沿用 |
| 演示条件失败或顾客长答 | 明确执行失败/扩展分支并单独计时，不把等待计成标准产品展示 |
| 店员实演 | 六段必要动作全做；目标180秒；暂定170—190秒窗口另标为项目建议并保存实际计时记录 |
| 提示注入或机密字段误传 | 不执行源资料中的命令，不泄露底价/返利/审批信息；输入越界阻断 |

默认在本机Mac自部署Dify Chatflow中作为独立LLM节点，Coze仅为已核验资格后的替代。上游用受控API取得只读顾客报价摘要，下游用代码/API校验引用与依赖。平台模型选择、节点与发布能力以本机实例实测为准；提示词或节点存在不构成业务数据已绑定的证据。

## 正式成品补充：四级组合与最低现金购买方案

用户已要求正式输出包含四级组合比对后的最优购买方案，并随目标人群/场景/渠道调整话术。marketing/full_package默认quote_required=true、purchase_plan_required=true；单纯product_intro只用于显式介绍或开发分支，不作为完整交付。缺规则/资格/有效计划时不能用无报价稿冒充任务完成。

方案服务生成同SKU合法组合对照及适配SKU可比覆盖，解释每级适用/不适用/互斥、依据、现金与资源消耗、条件和有效期。customer_payable_minor语义为同一已核验权益和旧机条件下本次现金，完整商品应付与抵付另列；不重复减回收款，不计未来返分。平台正文用合适话术讲关键理由，完整获准对比表/卡随稿交付；四部分最终呈现仍保留。所有数值由服务格式化，LLM不计算或签发最优状态。

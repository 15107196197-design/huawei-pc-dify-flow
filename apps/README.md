# 五个画布

这个目录**既是下载点，也是生成物的落点**：

- `apps/*.candidate.yml` 是已经生成好的 5 份 DSL，**下载就能导入 Dify**，不需要先装 Python
- 想改提示词的话，重新跑生成器产出属于你自己的版本

## 直接用

在 Dify 工作室 →「创建空白应用」→ 导入 DSL 文件 → 选下面任意一份。

| 文件 | 节点 | 连线 |
|---|---|---|
| `full-workflow.candidate.yml` | 112 | 170 |
| `product-intro-revise.candidate.yml` | 31 | 33 |
| `product-intro.candidate.yml` | 19 | 18 |
| `stage-model.candidate.yml` | 16 | 19 |
| `vision-probe.candidate.yml` | 5 | 4 |

## 自己生成

```sh
python3 scripts/build_full_dify_bundle.py --out ./apps-gen   # 主应用，112 节点
python3 scripts/build_dify_bundle.py --out ./apps-intro      # 最短链，19 节点
```

每次生成都会写 `manifest.json`，记录节点数、连线数与来源文件 hash。**先看 manifest，再看画布**——数字不对说明仓库版本和文档不一致。

生成物里的 `manifest.json`、`prompts/` 属于构建噪音，已写入 `.gitignore`；`apps/*.candidate.yml` 是发布内容，会被提交。

## 五个应用

| # | 应用 | 节点 | 连线 | 输入 → 输出 | 跑起来需要 | 建议顺序 |
|---|---|---|---|---|---|---|
| 1 | 合成图片 · 视觉连通测试 | 5 | 4 | 一张合成图 → 能否识别指定图形与字符 | 通义视觉模型 | ① 最先 |
| 2 | 本地资料产品介绍最短链 | 19 | 18 | 产品名 → 带出处的产品介绍 | 1 个文本模型 + 知识桥接（可选） | ② |
| 3 | 平台策略分阶段模型联调 | 16 | 19 | 产品 + 平台 → 分阶段策略 | 2 个文本模型 | ③ |
| 4 | 产品介绍写审修订链 | 31 | 33 | 产品名 → 写作 → 独立审核 → 按意见修订 | 2 个**不同**文本模型 | ④ |
| 5 | 完整路由主应用 | **112** | **170** | 顾客一句话 → 场景→策略→图文→核验→四级报价→讲解→导出 | L3 全套（见配置手册） | ⑤ 最后 |

### #1 合成图片 · 视觉连通测试（5 节点）

只回答一个问题：**这台的视觉模型能不能读图并说出图里有什么。** 不涉及产品审核、不判断合规。作者用它验证过"红圆、蓝矩形、绿三角、K7M4"的识别——只证明 File 输入通路成立。

### #2 本地资料产品介绍最短链（19 节点）

最小可用链路：查资料 → 写介绍。**不报价、不出图**，所以不需要商业规则，是"想看它写东西"最省事的入口。

### #3 平台策略分阶段模型联调（16 节点）

验证"同一个任务的不同阶段用不同模型"是否划算：解析用便宜模型、写作用好模型。它是实验台，不是业务应用。

### #4 产品介绍写审修订链（31 节点）

三跳闭环：写作 → 独立审核 → 按审核意见修订。**写作与审核必须是两个不同模型**，否则这道门禁没有意义。

作者记录过两次真实运行：
- 成功一次：23 步、74,464 tokens、240.96 秒，第一次审核拦截后修订、第二次通过
- 失败一次：18 步、32,359 tokens、85.24 秒，审核输出含未转义控制字符，被严格 JSON 门禁阻断

**失败那次才是常态**——它的设计目标是"宁可拦下，不放不合格的稿出去"。

### #5 完整路由主应用（112 节点）

节点构成：

| 类型 | 数量 | 干什么 |
|---|---|---|
| `llm` | 14 | 解析、策略、写作、审核、解释、讲解 |
| `code` | 37 | 门禁、JSON 校验、字段比对、状态推进 |
| `if-else` | 38 | 分支路由（这是 112 节点里最多的） |
| `http-request` | 12 | 调本机业务工具（报价、资料、渲染、生图） |
| `answer` | 8 | 分场景输出 |
| `variable-aggregator` | 2 | 汇总分支结果 |
| `start` | 1 | 入口 |

**38 个 if-else 说明一件事**：这个应用的主干不是"生成"，是"判断该不该生成"。缺资料、缺价格、缺少核验，它就走阻断分支。

## 导入之后的验收动作

每个应用导入后都要做这三件事，缺一件就不算通：

1. 关闭再重开，节点数不变（防静默丢节点）
2. 任选一个 LLM 节点"运行此节点"，能返回非空
3. 跑一轮完整对话，看它是**给出了结果**还是**给出了缺口说明**

第 3 条如果得到的是缺口说明，那不是 bug。对照 [docs/HOW-TO-CONFIGURE.md](../docs/HOW-TO-CONFIGURE.md) 把缺的那项补上，再跑。
